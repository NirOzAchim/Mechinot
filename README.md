# Mechinot

פלטפורמה שבה מכינה **מאפיינת לעצמה** אפליקציה ומקבלת פריסה משלה.

---

## איך מריצים

### ווינדוס — לחיצה כפולה על `start.cmd`

בסייר הקבצים, בתוך תיקיית `Mechinot`. זה הכול: הוא מושך את הקוד האחרון,
מתקין מה שחסר, מנקה את מטמון Vite, מרים את השרת ופותח את הדפדפן על
הקונסולה.

⚠⚠ **ומטרמינל — `.\start.cmd` ולא `start.cmd`.** PowerShell **אינו
מריץ קבצים מהתיקייה הנוכחית** בלי הקידומת, וההודעה שהוא נותן היא
*«The term 'start.cmd' is not recognized»* — כלומר «הקובץ לא קיים»,
בזמן שהוא קיים והבעיה היא אחרת לגמרי. זו הודעה שמפילה אנשים.
(ב-`cmd.exe` הרגיל `start.cmd` לבדו כן עובד — ולכן זה תלוי באיזה
טרמינל פתחת, וזה בדיוק מה שהופך את זה לבלתי ניתן לניחוש.)

⚠ **פקודה אחת ולא ארבע, וזו אינה נוחות.** ארבע פקודות שצריך לזכור את
הסדר שלהן הן ארבע הזדמנויות להיתקע, ובכל אחת הודעת השגיאה מדברת על
משהו אחר מהסיבה האמיתית — «your local changes would be overwritten»
על seed שכתב קובץ מזהים, `ReferenceError` על קוד תקין שהמטמון החזיק
ישן, ו-`EADDRINUSE` על חלון שנשכח פתוח. `start.cmd` מטפל בשלושתם.

### מק / לינוקס

```bash
git pull
rm -rf node_modules/.vite     # ⚠ אחרי משיכה שהוסיפה קבצי מקור
npm install
npm run dev
```

**בכניסה הראשונה** הקונסולה תבקש להקים מנהל-על — שם משתמש וסיסמה שאתה
בוחר. משם פותחים מכינות.

| מה | כתובת |
|---|---|
| הקונסולה — כל המכינות | `localhost:5180/console` |
| האפליקציה של מכינה | `localhost:5180/m/<מזהה>/` |

⚠ `localhost:5180` לבדו **מפנה לקונסולה** ואינו מציג אפליקציה. דף שמונה
את כל הלקוחות לכל מי שמגיע לכתובת הוא דליפה בלי שום תועלת.

בעלייה השרת מדפיס **אילו מכינות נטענו ומה הכתובת של כל אחת** — שרת
שאינו אומר במה הוא עובד הוא שרת שאפשר לבזבז מולו חצי שעה על «למה השם
לא נכון».

```bash
npm run root -- --user achim --pass "סיסמה ארוכה"   # מנהל-על משורת פקודה
npm run seed                                        # מכינה מלאה לבדיקה
npm run new -- "מכינת מיתרים לכיש" --slug meitarim  # מכינה ריקה
npm run check                                       # הבדיקות, בלי רשת
```

## המוצר הוא שלושה

| | מי נכנס | מה זה |
|---|---|---|
| **הקונסולה** `/console` | אני בלבד | כל המכינות: פתיחה, ארכוב, תמיכה |
| **הסטודיו** `/m/<slug>/` → הגדרות | ראש המכינה | האשף שבו מאפיינים |
| **האפליקציה** `/m/<slug>/` | המכינה | מה שהיא אפיינה לעצמה |

ומה שמחבר ביניהם הוא **מסמך אפיון אחד** לכל מכינה
(`.data/m/<slug>/profile.json`): קובץ קריא לאדם שאומר מה שם המכינה, איך
היא קוראת לדברים, מה דלוק ומה מבנה השנה. **זה החוזה היחיד.**

*(האתר והתשלום עדיין לא נבנו — כרגע אני פותח מכינה מהקונסולה.)*

## ⚠⚠ הגבול בין מכינות

```
/console                 הקונסולה
/api/admin/…             ה-API שלה. אין בו מכינה כלל.
/m/<slug>/               האפליקציה של מכינה
/m/<slug>/api/…          ה-API שלה. המכינה מהנתיב.
```

**המכינה נגזרת מהנתיב** — לא מכותרת, לא מפרמטר ולא מגוף הבקשה. מה
שהדפדפן מצהיר עליו אינו הרשאה.

**ההפרדה בפועל היא תיקיה לכל מכינה**, ולא טבלה משותפת עם עמודת `tenant`.
טבלה משותפת פירושה שכל שאילתה בכל מסך חייבת לזכור לסנן, ומי שיוסיף את
הבאה לא יזכור. תיקיה נפרדת היא הפרדה שאי אפשר לשכוח.

**ולסשן יש שתי הגנות, ושתיהן נחוצות:**

1. העוגייה מוגבלת ל־`Path=/m/<slug>` — הדפדפן אפילו לא שולח אותה למכינה
   אחרת. (וזה גם מה שמאפשר להיות מחובר לשתי מכינות בשתי לשוניות.)
2. ה-slug **חתום בתוך האסימון**, והשרת משווה. מזהי החשבונות רצים בכל
   מכינה בנפרד — «חשבון 1001» קיים בשתיהן ומצביע על שני אנשים שונים —
   ולכן אסימון בלי מכינה היה נקרא במקום השני **כמישהו אחר**. לא שגיאה,
   לא 401: התחזות שקטה.

`npm run check:tenancy` מריץ את זה על שתי מכינות זמניות, כולל המקרה
הזה בדיוק. ⚠ **סריקת טקסט אינה יכולה להוכיח את זה** — זו הטענה היחידה
במאגר שכשלונה הוא דליפה בין לקוחות, ולכן היא מורצת.

### ⚠ אין מצב ברמת המודול בשרת

עד שהייתה קונסולה, פריסה שווה מכינה וכל מטמון גלובלי היה נכון. מרגע
שיש מרשם, `let cache` בקובץ נתיב פירושו שמכינה אחת רואה — או **כותבת** —
את הנתונים של אחרת. המסד, הדלתא והפרופיל תלויים כולם באובייקט המכינה
(`ctx.tenant`), ו-`npm run check` נכשל על `let` ברמת המודול תחת
`server/routes/`.

### מנהל-על בתוך מכינה

הקונסולה חייבת דרך להיכנס לאפליקציה — אחרת «תמיכה» פירושה לבקש ממנהל
המכינה את הסיסמה שלו. שלוש החלטות מחזיקות את זה:

* **אינו מתחזה לאדם.** `personId` הוא `null` והשם הוא «מנהל-על». מערכת
  שבה התמיכה נכנסת כ«דוד» מייצרת יומן שמשקר על מי עשה מה.
* **זה נראה במסך** — רצועה אדומה בכל מסך. מי שלא רואה שהוא במצב הזה
  ישכח שהוא בו, ויערוך נתונים אמיתיים בטוח שהוא בדמו.
* **זה נרשם** ומוצג בקונסולה.
* ⚠ **ומה שעדיין חסר, במפורש:** המכינה עצמה אינה רואה את היומן. לפני
  לקוח משלם ראשון זו דרישה ולא נחמדות.

## שני המסמכים שהכול נגזר מהם

### `core/schema.js` — מה קיים במערכת

42 ישויות: שדות, טיפוסים וקשרים. אין בו לוגיקה, רק תיאור — כדי שאפשר
יהיה לקרוא אותו מכל כיוון: לייצר ממנו טבלאות, טופס, בדיקה ותיעוד.

### `core/catalog.js` — מה אפשר שיהיה במכינה

**20 מודולים · 45 מסכים · 11 תפקידים**, מסקר של האפליקציה שרצה בייצור
בניר עוז (42 מסכים ב-13 קבוצות ניווט, ומפת `DUTIES`). לכל מודול יש
משפט **«מה זה נותן»** — זה מה שמנהל מכינה קורא באשף כשהוא מחליט, ולכן
זו אינה כותרת טכנית אלא הבטחה.

הקטלוג מזין את האשף, את הניווט, את ההרשאות ואת הבדיקות. **מודול חדש
הוא ערך שם, ולא נגיעה בשמונה קבצים.**

### `core/profile.js` — מה ניתן לאפיון

```
שכבה 1 · מילים      תמיד ניתנות לעריכה
שכבה 2 · מודולים    ניתנים לכיבוי מלא
שכבה 3 · מבנה       ⚠ קבוע, ולא יהיה אחרת
```

`STRUCTURE` מוצהר במפורש — שבוע ראשון-שבת, נוכחות לפי יום, מדריך→ראש.
מכינה שהמבנה שלה שונה אינה «הגדרה חסרה»; היא סיבה לשנות את הסכימה
לכולם, או לקוח שעוד לא בשל.

## תשע החלטות שאסור לשבור

**1. `slug` נשמר, `label` מוצג.** השורה במסד נושאת `role:kitchen`; המסך
מציג «אחראי מטבח» או «רכז מזון». במערכת הקודמת השם העברי היה המפתח
הראשי, וזו בדיוק הנקודה שנשברת אצל הלקוח השני. `npm run check` נכשל על
כל מפתח עברי בסכימה, ב-enum או ב-slug. **וזה חל גם על המכינה עצמה:**
ה-slug שבכתובת קבוע, והשם שמוצג משתנה מתי שרוצים.

**2. התבנית היא המוצר; האשף רק עורך אותה.** מכינה חדשה מתחילה מ-
`core/presets/premil.js` ומשנה את מה ששלה. מסמך אפיון הוא **דלתא מעל
תבנית** — ולכן תיקון בתבנית מגיע לכל המכינות.

**3. שכבת הגישה היא פעלים, לא שאילתות.** `list · get · create · update ·
remove`. במערכת הקודמת התפר היה `gql(מחרוזת GraphQL)`, ולכן אי אפשר היה
לשים מאחוריו שום דבר אחר. המנוע היום הוא קובץ JSON, **וזה זמני** —
החלפתו היא `server/data/file-engine.js` בלבד.

**4. כשל טעינה נראה אחרת מ«אין נתונים».** תמיד, בכל מסך. באנר אדום מול
מצב ריק מנוסח. זה באג שחי יומיים בייצור במערכת הקודמת. **וגם בקונסולה:**
מכינה שקובץ הנתונים שלה פגום מקבלת כרטיס אדום עם הסיבה ואינה נעלמת
מהרשימה — היא בדיוק זו שצריך לטפל בה.

**5. «לא סומן» הוא מצב ולא היעדר מצב.** יום שאיש לא סימן ויום שכולם
נעדרו בו חייבים להיראות אחרת.

**6. שולחים את המצב הרצוי, לא «הפוך».** שני אנשים שלוחצים כמעט יחד
שולחים אותה כוונה ומקבלים אותה תוצאה.

**7. מיפוי מפורש ולא פריסה.** כל נקודת קצה שמחזירה אדם בונה את התשובה
משדות מנויים. שדה שיתווסף לסכימה מחר לא ידלוף החוצה מעצמו.

**8. דלת אחת לשרת.** `client/api.js`. אין `fetch` בשום מקום אחר —
`npm run check` נכשל על כך. ⚠ **ושתי דלתות ולא אחת עם דגל**: `call`
לאפליקציה ו-`callAdmin` לקונסולה. פונקציה אחת עם דגל הייתה יוצרת בדיוק
את הבאג שבו קריאה של הקונסולה נשלחת לתוך מכינה.

**9. שום פעולה בקונסולה אינה נוגעת בנתוני חניכים.** היא יודעת **כמה**
חניכים יש במכינה, לא מי הם. מי שרוצה להסתכל פנימה נכנס לאפליקציה, וזה
נרשם. ההפרדה בין «ניהול המוצר» לבין «צפייה בנתונים» היא מה שהופך את
הראשון לבטוח.

## הסטודיו — שבעה שלבים

`client/Studio.jsx`. מנהל מכינה נכנס לפריסה ריקה, ו**האשף נפתח מעצמו**
כי שלבי החובה חסרים.

| | שלב | מה קורה בו |
|---|---|---|
| 1 | **זהות** ⚠ | שם, לוגו וצבעים. שינוי צבע נראה **מיד** על המסך עצמו |
| 2 | אוצר מילים | «חניך» או «תלמיד». המפתח נשמר, התווית מוצגת |
| 3 | **תפקידים** ⚠ | אילו תפקידים קיימים ואילו מסכים כל אחד פותח |
| 4 | מודולים | 20 כרטיסים עם «מה זה נותן». מה שכבוי **לא קיים** |
| 5 | **מבנה השנה** ⚠ | תאריכים, מכסות, וסף הצגת אחוזים |
| 6 | אנשים | **הדבקה** מגיליון · תצוגה מקדימה · אישור |
| 7 | נהלים | טקסטים שנערכים תמיד |

⚠ **שלושה חובה, ארבעה שאפשר לדלג עליהם.** מכינה צריכה להגיע
לאפליקציה עובדת תוך רבע שעה.

⚠⚠ **האשף אינו חד-פעמי** — אותם מסכים הם «הגדרות המכינה» אחר כך.
אשף שרץ פעם ונעלם מייצר מוצר שאי אפשר לתקן בו טעות.

### ההדבקה

`core/import.js` — **פרסור אחד למסך ולשרת.** שתי גרסאות היו נפרדות זו
מזו בתיקון הראשון, ואז המנהל מאשר בתצוגה המקדימה דבר אחד ומקבל אחר.

חמישה מייבאים: חניכים · צוות · לוח שנה · גיליונות מרצים · מסגרות.
מזהה עמודות **לפי צורה ולא לפי מיקום** — מנהל מדביק מהגיליון שלו, וסדר
העמודות שלו אינו שלנו. טאב, פסיק ושני רווחים מופרדים באותה הדבקה;
«בן»/«בת» ו«זכר»/«נקבה»; טווח תאריכים בתא אחד.

⚠ **ושתי רשימות דחייה נפרדות** — מה שהפרסור דחה ומה שהמסד סירב. בלי
ההפרדה שתיהן נראות כמו «לא נקלטה», והמנהל לא יודע מה לתקן.

## ⚠ מה שעוד לא קיים

* **האתר והתשלום.** הקונסולה והאשף בנויים ועובדים; מה שחסר הוא המכירה
  והפריסה האוטומטית — כרגע אני פותח מכינה בעצמי.
* **מסד נתונים אמיתי.** המנוע הנוכחי הוא קובץ JSON לכל מכינה: אין
  טרנזקציות, אין נעילה, ואין שני תהליכים בו-זמנית.
  **מתאים לפיתוח ולא לייצור.**
* **רוב המסכים.** בנויים: בית · אנשים · נוכחות · הסטודיו · הקונסולה.
  השאר קיימים בקטלוג, יש להם הרשאות וניווט, **ומסך שאומר במפורש שהוא
  טרם נבנה** — כי מנהל שהדליק מודול ולא רואה את המסך יסיק שההדלקה לא
