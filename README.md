# Mechinot

פלטפורמה שבה מכינה **מאפיינת לעצמה** אפליקציה ומקבלת פריסה משלה.

```bash
npm install
npm run dev      # http://localhost:5180
```

**שתי דרכים להתחיל:**

```bash
# מכינה חדשה וריקה — נכנסים, והאשף נפתח מעצמו
npm run new -- "מכינת מיתרים לכיש" --user meitarim --head "אבישי כהן"

# או מכינה מלאה לבדיקה
npm run seed
```

## המוצר הוא שניים

**הסטודיו** — פריסה אחת. אתר, תשלום, והאשף שבו מאפיינים. *(טרם נבנה.)*
**האפליקציה** — פריסה לכל מכינה, מסד נתונים משלה, לא יודעת שיש עוד מכינות.

ומה שמחבר ביניהם הוא **מסמך אפיון אחד** (`.data/profile.json`): קובץ קריא
לאדם שאומר מה שם המכינה, איך היא קוראת לדברים, מה דלוק ומה מבנה השנה.
הפריסה היא «הרץ אפליקציה עם המסמך הזה». **זה החוזה היחיד.**

---

## שני המסמכים שהכול נגזר מהם

### `core/schema.js` — מה קיים במערכת

ישויות, שדות, טיפוסים וקשרים. אין בו לוגיקה, רק תיאור — כדי שאפשר יהיה
לקרוא אותו מכל כיוון: לייצר ממנו טבלאות, טופס, בדיקה ותיעוד.

### `core/catalog.js` — מה אפשר שיהיה במכינה

**20 מודולים · 45 מסכים · 11 תפקידים**, מסקר של האפליקציה שרצה בייצור
בניר עוז (42 מסכים ב-13 קבוצות ניווט, ומפת `DUTIES`). לכל מודול יש
משפט **«מה זה נותן»** — זה מה שמנהל מכינה קורא באשף כשהוא מחליט, ולכן
זו אינה כותרת טכנית אלא הבטחה.

הקטלוג מזין את האשף, את הניווט, את ההרשאות ואת הבדיקות. **מודול חדש
הוא ערך שם, ולא נגיעה בשמונה קבצים.**

### `core/profile.js` — מה ניתן לאפיון

```
שכבה 1 · מילים      תמיד ניתנות לעריכה
שכבה 2 · מודולים    ניתנים לכיבוי מלא
שכבה 3 · מבנה       ⚠ קבוע, ולא יהיה אחרת
```

`STRUCTURE` מוצהר במפורש — שבוע ראשון-שבת, נוכחות לפי יום, מדריך→ראש.
מכינה שהמבנה שלה שונה אינה «הגדרה חסרה»; היא סיבה לשנות את הסכימה
לכולם, או לקוח שעוד לא בשל.

## שמונה החלטות שאסור לשבור

**1. `slug` נשמר, `label` מוצג.** השורה במסד נושאת `role:kitchen`; המסך
מציג «אחראי מטבח» או «רכז מזון». במערכת הקודמת השם העברי היה המפתח
הראשי, וזו בדיוק הנקודה שנשברת אצל הלקוח השני. `npm run check` נכשל על
כל מפתח עברי בסכימה, ב-enum או ב-slug.

**2. התבנית היא המוצר; האשף רק עורך אותה.** מכינה חדשה מתחילה מ-
`core/presets/premil.js` ומשנה את מה ששלה. מסמך אפיון הוא **דלתא מעל
תבנית** — ולכן תיקון בתבנית מגיע לכל המכינות.

**3. שכבת הגישה היא פעלים, לא שאילתות.** `list · get · create · update ·
remove`. במערכת הקודמת התפר היה `gql(מחרוזת GraphQL)`, ולכן אי אפשר היה
לשים מאחוריו שום דבר אחר. המנוע היום הוא קובץ JSON, **וזה זמני** —
החלפתו היא `server/data/file-engine.js` בלבד.

**4. כשל טעינה נראה אחרת מ«אין נתונים».** תמיד, בכל מסך. באנר אדום מול
מצב ריק מנוסח. זה באג שחי יומיים בייצור במערכת הקודמת.

**5. «לא סומן» הוא מצב ולא היעדר מצב.** יום שאיש לא סימן ויום שכולם
נעדרו בו חייבים להיראות אחרת.

**6. שולחים את המצב הרצוי, לא «הפוך».** שני אנשים שלוחצים כמעט יחד
שולחים אותה כוונה ומקבלים אותה תוצאה.

**7. מיפוי מפורש ולא פריסה.** כל נקודת קצה שמחזירה אדם בונה את התשובה
משדות מנויים. שדה שיתווסף לסכימה מחר לא ידלוף החוצה מעצמו.

**8. דלת אחת לשרת.** `client/api.js`. אין `fetch` בשום מקום אחר —
`npm run check` נכשל על כך.

## מבנה

```
core/            המוח. בלי UI, בלי שרת, בלי מסד.
  schema.js        מה קיים
  profile.js       מה ניתן לאפיון + ולידציה
  vocab.js         slug → label
  presets/         תבניות. תבנית שנייה = קובץ נוסף, לא דגל.

server/
  index.js         שרת Node אחד. לא Vercel, לא פונקציות.
  auth.js          scrypt, עוגייה חתומה, guard
  profile-store.js טעינת הדלתא ומיזוגה עם התבנית
  data/store.js    חוזה הגישה + ולידציה מול הסכימה
  data/file-engine.js  ⚠ מנוע זמני
  routes/index.js  מפת נקודות הקצה — השער של כל אחת גלוי שם

client/
  api.js           הדלת היחידה
  styles.js        ⚠ אין הקס מחוץ ל-:root. הצבעים מהאפיון.

tools/
  seed.mjs         מכינה לדוגמה
  check.mjs        הבדיקות
```

## הסטודיו — שבעה שלבים

`client/Studio.jsx`. מנהל מכינה נכנס לפריסה ריקה, ו**האשף נפתח מעצמו**
כי שלבי החובה חסרים.

| | שלב | מה קורה בו |
|---|---|---|
| 1 | **זהות** ⚠ | שם, לוגו וצבעים. שינוי צבע נראה **מיד** על המסך עצמו |
| 2 | אוצר מילים | «חניך» או «תלמיד». המפתח נשמר, התווית מוצגת |
| 3 | **תפקידים** ⚠ | אילו תפקידים קיימים ואילו מסכים כל אחד פותח |
| 4 | מודולים | 20 כרטיסים עם «מה זה נותן». מה שכבוי **לא קיים** |
| 5 | **מבנה השנה** ⚠ | תאריכים, מכסות, וסף הצגת אחוזים |
| 6 | אנשים | **הדבקה** מגיליון · תצוגה מקדימה · אישור |
| 7 | נהלים | טקסטים שנערכים תמיד |

⚠ **שלושה חובה, ארבעה שאפשר לדלג עליהם.** מכינה צריכה להגיע
לאפליקציה עובדת תוך רבע שעה.

⚠⚠ **האשף אינו חד-פעמי** — אותם מסכים הם «הגדרות המכינה» אחר כך.
אשף שרץ פעם ונעלם מייצר מוצר שאי אפשר לתקן בו טעות.

### ההדבקה

`core/import.js` — **פרסור אחד למסך ולשרת.** שתי גרסאות היו נפרדות זו
מזו בתיקון הראשון, ואז המנהל מאשר בתצוגה המקדימה דבר אחד ומקבל אחר.

חמישה מייבאים: חניכים · צוות · לוח שנה · גיליונות מרצים · מסגרות.
מזהה עמודות **לפי צורה ולא לפי מיקום** — מנהל מדביק מהגיליון שלו, וסדר
העמודות שלו אינו שלנו. טאב, פסיק ושני רווחים מופרדים באותה הדבקה;
«בן»/«בת» ו«זכר»/«נקבה»; טווח תאריכים בתא אחד.

⚠ **ושתי רשימות דחייה נפרדות** — מה שהפרסור דחה ומה שהמסד סירב. בלי
ההפרדה שתיהן נראות כמו «לא נקלטה», והמנהל לא יודע מה לתקן.

## ⚠ מה שעוד לא קיים

* **האתר והתשלום.** האשף עצמו בנוי ועובד; מה שחסר הוא המכירה
  והפריסה האוטומטית — כרגע `npm run new` עושה את זה ביד.
* **מסד נתונים אמיתי.** המנוע הנוכחי הוא קובץ JSON: אין טרנזקציות, אין
  נעילה, ואין שני תהליכים בו-זמנית. **מתאים לפיתוח ולא לייצור.**
* **רוב המסכים.** בנויים: בית · אנשים · נוכחות · הסטודיו. השאר קיימים
  בקטלוג, יש להם הרשאות וניווט, **ומסך שאומר במפורש שהוא טרם נבנה** —
  כי מנהל שהדליק מודול ולא רואה את המסך יסיק שההדלקה לא עבדה.
* **העניינים המשפטיים.** נתוני קטינים דורשים DPA, מדיניות פרטיות
  ורישום מאגר לפני הלקוח המשלם הראשון.

## ההשראה

`MechinaManagerWide` הוא מערכת שרצה בייצור במכינת ניר עוז על monday,
ובה 5,100 שורות תיעוד שכל אזהרה בהן היא באג ששולם עליו. **לוקחים
משם את ההחלטות ואת הנימוקים — לא את הקוד, ולא שום דבר שנוגע ב-monday.**
